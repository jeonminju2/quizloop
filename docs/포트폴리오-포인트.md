# 포트폴리오 포인트

"그냥 GPT로 문제 만들어봤어요" 프로젝트와 구분되는, 면접·서류에서 세게 밀 수 있는 지점들.

## 1. 핵심 한 줄 피치

"문제를 생성하는 도구가 아니라, 학생이 뭘 모르는지 찾아서 그것만 다시 가르치는 폐루프(closed-loop) 학습 시스템을 만들었다."

## 2. 기술적으로 어필할 수 있는 포인트

### (1) RAG 기반 grounding — 환각 방지 설계
- 단순히 LLM에 "문제 만들어줘"라고 던지지 않고, 업로드 자료를 청크·임베딩해서 검색된 근거(chunk) 안에서만 문제를 생성하도록 강제.
- `questions.source_chunk_id`로 모든 문제의 출처를 역추적 가능 → "이 문제, 자료 몇 페이지 기반이에요"를 보여줄 수 있음.
- 어필 포인트: "생성형 AI의 환각 문제를 어떻게 구조적으로 억제했는가"에 대한 구체적 답변이 가능해짐.

### (2) 구조화 출력 설계 (Structured Output)
- 문제 생성/채점/오답분류 전부 고정 JSON 스키마로 강제 → 프롬프트 엔지니어링 + 파싱 안정성 경험을 구체적으로 설명 가능.
- 어필 포인트: "LLM 응답을 프로덕션에서 안정적으로 파싱 가능한 형태로 강제하는 설계 경험."

### (3) 오답 유형 분류 로직 (데이터 모델링 + 프롬프트 설계)
- 오답을 "단순 실수 / 개념 혼동 / 미학습"으로 나누는 분류기를 직접 설계 → 단순 정오답 채점기가 아니라는 걸 데이터 모델(`wrong_answer_tags`)로 증명.
- 어필 포인트: "채점을 넘어 오답의 '이유'를 분류하는 분석 레이어를 설계한 경험" — 교육 도메인에서 흔치 않은 차별점.

### (4) 재출제 루프 및 정량적 개선 지표
- `quiz_sets.source_quiz_set_id`로 1차→재출제 계보를 남겨서, "재시험 후 정답률이 몇 % 올랐는지" 같은 Before/After 지표를 제품 안에서 직접 계산.
- 어필 포인트: 포트폴리오에 "정성적 설명"이 아니라 "정량적 결과 지표"를 넣을 수 있는 몇 안 되는 구조. (예: "취약 개념 3회 재출제 후 해당 개념 정답률 평균 X%p 상승")

### (5) 벡터 검색 + 관계형 DB 통합 설계
- pgvector로 임베딩 검색과 정형 데이터를 한 DB에서 관리 → 인프라 단순화 판단 근거를 설명할 수 있음.

## 3. 데모/발표에서 쓸 수 있는 시나리오

1. 강의자료 PDF 업로드 → 실시간으로 문제 10개 생성되는 것 보여주기
2. 일부러 취약한 개념 위주로 오답 제출
3. "취약 개념: OOO (오답률 80%)" 같은 분석 결과 즉시 표시
4. "이 개념만 다시 풀기" 클릭 → 재출제된 문제로 재시험
5. 1차 vs 2차 정답률 비교 그래프로 마무리 ("이게 이 프로젝트가 존재하는 이유")

이 5단계 흐름 자체가 포트폴리오 시연 영상/발표 스토리라인으로 바로 쓸 수 있음.

## 4. 서류/면접에서 나올 법한 질문 대비

- **"기존 서비스(큐레카 등)와 뭐가 다른가?"** → 생성으로 끝나지 않고 오답 분석·재출제까지 도는 폐루프 구조, 데이터 모델(`wrong_answer_tags`, `weak_concept_stats`)로 증명 가능.
- **"LLM 환각은 어떻게 막았나?"** → RAG grounding + source_chunk_id 추적.
- **"정량적 성과가 있나?"** → 재출제 전후 정답률 변화 지표 설계·측정.
- **"왜 이 프로젝트를 만들었나?"** → 학생 입장에서 진짜 도움이 되는 방향(약점 교정)에 초점을 맞췄다는 동기 서술.
