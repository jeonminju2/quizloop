# 포트폴리오 포인트

"그냥 GPT로 문제 만들어봤어요" 프로젝트와 구분되는, 면접·서류에서 세게 밀 수 있는 지점들.

## 1. 핵심 한 줄 피치

"문제를 생성하는 도구가 아니라, 학생이 뭘 모르는지 찾아서 그것만 다시 가르치는 폐루프(closed-loop) 학습 시스템을 만들었다."

## 2. 기술적으로 어필할 수 있는 포인트

### (1) RAG 기반 grounding — 환각 방지 설계
- 단순히 LLM에 "문제 만들어줘"라고 던지지 않고, 업로드 자료를 청크·임베딩해서 검색된 근거(chunk) 안에서만 문제를 생성하도록 강제.
- `questions.source_chunk_id`로 모든 문제의 출처를 역추적 가능 → "이 문제, 자료 몇 페이지 기반이에요"를 보여줄 수 있음.
- 어필 포인트: "생성형 AI의 환각 문제를 어떻게 구조적으로 억제했는가"에 대한 구체적 답변이 가능해짐.

### (2) 구조화 출력 설계 (Structured Output)
- 문제 생성/채점/오답분류 전부 고정 JSON 스키마로 강제 → 프롬프트 엔지니어링 + 파싱 안정성 경험을 구체적으로 설명 가능.
- 어필 포인트: "LLM 응답을 프로덕션에서 안정적으로 파싱 가능한 형태로 강제하는 설계 경험."

### (3) 오답 유형 분류 로직 (데이터 모델링 + 프롬프트 설계)
- 오답을 "단순 실수 / 개념 혼동 / 미학습"으로 나누는 분류기를 직접 설계 → 단순 정오답 채점기가 아니라는 걸 데이터 모델(`wrong_answer_tags`)로 증명.
- 어필 포인트: "채점을 넘어 오답의 '이유'를 분류하는 분석 레이어를 설계한 경험" — 교육 도메인에서 흔치 않은 차별점.

### (4) 재출제 루프 및 정량적 개선 지표
- `quiz_sets.source_quiz_set_id`로 1차→재출제 계보를 남겨서, "재시험 후 정답률이 몇 % 올랐는지" 같은 Before/After 지표를 제품 안에서 직접 계산.
- 어필 포인트: 포트폴리오에 "정성적 설명"이 아니라 "정량적 결과 지표"를 넣을 수 있는 몇 안 되는 구조. (예: "취약 개념 3회 재출제 후 해당 개념 정답률 평균 X%p 상승")

### (5) 벡터 검색 + 관계형 DB 통합 설계
- pgvector로 임베딩 검색과 정형 데이터를 한 DB에서 관리 → 인프라 단순화 판단 근거를 설명할 수 있음.
- 임베딩 provider는 Voyage AI(voyage-4)로 선정 — "왜 OpenAI가 아니라 Voyage인가"에 "Anthropic 공식 RAG 파트너, 다국어(한국어) 지원, 계정당 2억 토큰 무료"로 근거 있게 답할 수 있음.

### (6) 실제 로컬 Postgres+pgvector로 엔드투엔드 테스트 → 실제 버그 발견·수정
- 업로드 → 청크분할/개념추출 → 문제생성 → 채점 → 오답분석 → 재출제 → before/after 비교까지 전체 플로우를 FastAPI TestClient + 실제 Postgres로 태워서 검증. LLM 호출만 mock(비용/키 없이도 파이프라인 검증 가능하게)하고 나머지는 전부 실제 코드 경로.
- 이 과정에서 `weak_concept_stats` 신규 레코드 생성 시 SQLAlchemy 컬럼 default가 flush 전 파이썬 객체에는 반영 안 되는 것 때문에 `TypeError: NoneType + int`가 나는 실제 버그를 발견·수정함.
- 어필 포인트: "테스트를 짜서 실제로 버그를 잡아본 경험"은 말로만 하는 것보다 증명력이 훨씬 큼 — 어떤 버그였는지, 왜 발생했는지, 어떻게 고쳤는지 구체적으로 설명 가능.

### (7) 개인화 — 교수님 시험 스타일 반영
- 학생이 과목별로 "이 교수님 시험 스타일"을 자유 텍스트로 한 번 적어두면(`materials.exam_style_note`), 이후 모든 문제 생성·재출제에 자동으로 반영됨 (형식/난이도 분포/표현 방식).
- 어필 포인트: "개인화가 grounding(환각 방지) 원칙을 깨지 않도록 설계" — 스타일은 '어떻게 묻는지'에만 관여하고 '무엇을 묻는지'는 여전히 근거 자료로 제한한다는 프롬프트 설계 원칙을 구체적으로 설명 가능.

### (8) 오답분석 v2 — 구조적 최적화로 LLM 호출 자체를 없앰
- v1은 오답을 낼 때마다 "이 오답이 어느 개념과 헷갈린 건지"를 매번 LLM에게 추론시켰음(느리고, 비용 들고, 판정이 매번 미세하게 달라질 수 있음).
- v2에서는 **문제 생성 시점**에 LLM이 각 객관식 보기가 어떤 개념을 나타내는지(`related_concept`)를 같이 답하게 하고, 이를 `question_options.related_concept_id`로 DB에 고정 저장. 학생이 그 보기를 고르면 오답분석이 이 값을 바로 조회해서 **LLM 호출 없이 즉시 concept_confusion으로 판정**.
- 어필 포인트: "런타임 LLM 호출을 생성 시점으로 앞당겨서 반복되는 추론 비용을 구조적으로 제거한 경험" — 단순히 프롬프트를 잘 쓰는 것을 넘어, LLM 호출 자체를 언제 어디서 할지 설계하는 판단.

### (9) 인증·인가 설계 — 존재 자체를 숨기는 404
- JWT(PyJWT) + bcrypt를 직접 구현(passlib 같은 무거운 의존성 없이). 모든 자료/문제 엔드포인트가 `Authorization: Bearer` 토큰으로 유저를 식별하고, 소유권을 확인.
- 남의 자료·문제 세트에 접근하면 403이 아니라 **404**를 반환 — "권한이 없다"는 사실 자체가 "그런 자원이 존재한다"는 정보를 흘리는 걸 막기 위한 의도적 설계. 로그인 실패 메시지도 "이메일 없음"과 "비밀번호 틀림"을 구분하지 않고 동일하게 반환(등록된 이메일 목록을 추측 못 하게).
- 어필 포인트: "기능만 되는 인증이 아니라, 정보 노출 표면을 줄이는 방향으로 설계한 경험."

### (10) 백그라운드 큐 — 인프라 없이도 항상 동작하는 그레이스풀 폴백
- 자료 처리(텍스트추출/OCR/임베딩/개념추출)를 RQ+Redis 기반 백그라운드 큐로 분리해서 업로드 요청이 즉시 응답하게 만듦.
- Redis가 안 떠있으면(로컬 개발, 테스트 환경 등) 예외를 잡아서 **그 자리에서 동기로 즉시 처리**하는 폴백 경로로 자동 전환 — 추가 인프라 없이도 앱 자체는 항상 동작하되, 실제 서비스 환경에서는 워커를 띄우면 진짜 비동기로 동작.
- 어필 포인트: "인프라 의존성을 필수가 아니라 선택으로 설계" — 로컬 개발/CI 환경과 프로덕션 환경이 같은 코드 경로로 동작하도록 만든 판단.

### (11) 스캔 이미지 PDF OCR — 실패를 조용히 흡수하는 설계
- 텍스트 레이어가 있는 페이지는 기존 방식(빠르고 정확) 그대로 두고, **텍스트 레이어가 없는 페이지만 골라서** OCR(tesseract + 한국어 언어팩)로 재시도하는 하이브리드 추출.
- poppler/tesseract가 시스템에 없어도 예외를 잡아서 그 페이지만 스킵하고 나머지 파이프라인은 계속 진행 — 선택적 의존성이 없다고 전체가 죽지 않게 설계.
- 어필 포인트: "여러 추출 전략을 계층화하고, 각 계층의 실패를 전체 실패로 전파시키지 않는 방어적 설계."

## 3. 데모/발표에서 쓸 수 있는 시나리오

1. 강의자료 PDF 업로드 → 실시간으로 문제 10개 생성되는 것 보여주기
2. 일부러 취약한 개념 위주로 오답 제출
3. "취약 개념: OOO (오답률 80%)" 같은 분석 결과 즉시 표시
4. "이 개념만 다시 풀기" 클릭 → 재출제된 문제로 재시험
5. 1차 vs 2차 정답률 비교 그래프로 마무리 ("이게 이 프로젝트가 존재하는 이유")

이 5단계 흐름 자체가 포트폴리오 시연 영상/발표 스토리라인으로 바로 쓸 수 있음.

## 4. 서류/면접에서 나올 법한 질문 대비

- **"기존 서비스(큐레카 등)와 뭐가 다른가?"** → 생성으로 끝나지 않고 오답 분석·재출제까지 도는 폐루프 구조, 데이터 모델(`wrong_answer_tags`, `weak_concept_stats`)로 증명 가능.
- **"LLM 환각은 어떻게 막았나?"** → RAG grounding + source_chunk_id 추적.
- **"정량적 성과가 있나?"** → 재출제 전후 정답률 변화 지표 설계·측정.
- **"왜 이 프로젝트를 만들었나?"** → 학생 입장에서 진짜 도움이 되는 방향(약점 교정)에 초점을 맞췄다는 동기 서술.
